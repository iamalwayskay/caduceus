Caduceus

A telemetry-free fork of T3 Code, deployed as one control surface across Kay's laptop and Haven. Hermes and DeepSeek Harness remain separate ACP providers; project files remain shared memory.

Architecture

Placement contract

Code/AI/
├── apps/caduceus/                 fork source; origin is Kay, upstream is pingdotgg
│   ├── apps/server/               orchestration, analytics removal, ACP launch
│   ├── apps/web/                  remove analytics controls/copy; retain local diagnostics
│   ├── apps/desktop/              remove outbound renderer/crash telemetry
│   ├── apps/mobile/               remove outbound traces/log export
│   ├── packages/shared/           hard-disable telemetry configuration
│   └── docs/plans/                this editable plan

Laptop: ~/.local/bin/caduceus → built launcher; user service points at the fork build.
Haven:  /srv/caduceus/{app,config,data}; hardened system service runs the same commit.

Phases

1. Map and pin every network telemetry path

Classify product analytics, OTLP export, desktop/mobile reporting and developer task telemetry. Preserve local trace files, resource diagnostics, provider usage accounting, updates, model catalogs and local pairing. Reject T3 cloud auth, relay and activity publishing as outside the trust boundary.

Checked by: a committed inventory test fails on the untouched upstream source and names every forbidden module/config key.

2. Make outbound telemetry impossible

Delete network publishers and their settings surfaces; make configuration parsers reject or ignore telemetry destinations. Environment variables cannot turn it back on. Remove privacy copy that claims anonymous usage collection.

Checked by: focused server, web, desktop, mobile and build-tool tests plus a source scan with an explicit allow-list for local diagnostics.

3. Build the fork and replace the laptop service

Build the self-contained Linux CLI from source. Make a recoverable offline copy of live user data from data/t3code into data/caduceus, excluding stale launcher/service metadata, switch the service atomically, and retain the stock home and unit until verification passes.

Checked by: exact commit/build identity, service ExecStart and home readback, existing project visible, and process-attributed socket/DNS capture showing only allow-listed functional destinations.

4. Wire providers through ACP using CLI-owned state

Add Hermes (hermes acp) and DSH (dsh --profile acp) with absolute executable paths and DSH_HOME. Use the UI only if upstream exposes no CLI/API for provider-instance writes.

Checked by: each provider completes a read-only turn in /home/kay/Code/AI; both see the same project files.

5. Deploy the same commit to Haven and link both machines

Provision the caduceus workload with Haven's native workload tooling under /srv/caduceus, run it as locked svc-caduceus, and keep it bound to Haven loopback. A laptop user service forwards a second loopback port over the existing authenticated SSH route; Caduceus registers that URL as an ordinary saved environment. T3 accounts, Clerk, Cloudflare relay and T3-hosted services are not involved.

Checked by: Haven's complete acceptance contract (identity, ACL denial, unit verification/security, listeners, failure/restart/reboot, backup/restore and secret scan), tunnel restart and denial tests, exact commit identity, both local HTTP health endpoints, and successful read-only ACP turns from every installed provider.

2026-10-28 corrective acceptance

The fork is not accepted because a build exists. It is accepted only when the installed application survives a clean launch and the user-visible state below is proven from that application. Manual database edits are migration inputs, never the finished fix.

6. Make the installed application the single entry point

The application-menu entry, CLI activation command and direct AppImage launch resolve the same Caduceus home, desktop environment and provider executables. A completed installation never re-enters onboarding, and activation opens the requested existing project without creating another server or checkout.

Checked by: automated desktop environment/onboarding regressions, a cold application-menu launch, caduceus app /home/kay/Desktop/Mirius, one backend owner, and a visible Mirius project tree.

7. Import conversations with stable project and title identity

Active and archived Codex/Claude transcripts deduplicate by provider session identity. Explicit project metadata wins over cwd; when only cwd exists, a persisted assignment map preserves user corrections. Structured wrapper text is skipped when choosing a title, and truncation is reported instead of being called “all history.”

Checked by: red/green fixtures for Projectless-versus-Mirius assignment, archived duplicates, attachment wrappers, explicit titles, compressed archives and every safety-limit result; then compare imported source IDs and titles against the real Mirius and Projectless inventories.

8. Prove providers and usage from the installed runtime

The picker exposes exactly Codex, Claude, DSH: Local models, Venice and OpenCode Go. Each group is backed by an executable provider and its own filtered model inventory, not merely a display label. Usage defaults to token counts and handles local/unpriced models without hiding subscription usage where it exists.

Checked by: provider health/model-list reads from the desktop-safe environment, one harmless turn per available provider family, and visible token usage after a new turn.

9. Use Hermes as the shared project-memory application

Caduceus does not invent a second memory service. Local and frontier agents share the same ordinary project memory files; Hermes performs its existing recursive learning over those files. Git synchronizes durable memory between the laptop and Haven, while session transcripts remain available to every provider through Caduceus.

Checked by: a memory written through one provider is read through another, Hermes records its learning in the project-owned location, and the same committed memory is visible from Haven without copying secrets or machine-local state.

10. Ship one clean, recoverable release

Build outputs live outside the source tree, the development branch tracks Kay's private remote, installed desktop and CLI artifacts identify the exact commit, and stale release directories are archived or removed only after their installed replacements are verified.

Checked by: clean Git status, tracked remote branch, artifact hashes, installed launcher readback, full relevant test suites, production build and final desktop smoke test.

Resolved decisions

  • Name: Caduceus. It is a one-word fork name and keeps upstream as upstream.
  • Telemetry: remove network analytics and crash/trace export. Keep diagnostics that remain on the machine.
  • Remote access: remove T3 cloud authentication, relay and publishing from the product entry points. Use an SSH local forward owned by the laptop user; both servers remain loopback-only.
  • Memory: ordinary project files curated by Hermes. Git is the cross-machine authority: each host uses its own clone, pulls before work, and commits/pushes durable memory with provenance. Non-Git folders are local-only until explicitly placed under version control. No memory MCP service.
  • Mobile: remove mobile telemetry from source, but do not claim the stock App Store/Play client is telemetry-free. This pass uses the fork's local web client; a signed Caduceus mobile build is a later deliverable.
  • Activity publication: remove the T3 publishing route with the rest of the hosted Connect surface.
  • Rollout: laptop first, Haven second; the stock T3 install remains recoverable until both pass.

Out of scope

  • Reimplementing Hermes learning algorithms inside Caduceus; the existing Hermes application is integrated as the learner.
  • Copying DSH or Unsloth internals into the fork.
  • Removing provider authentication, local client pairing, update checks or provider catalogs merely because they use the network.
  • Publishing mobile-store binaries in this pass.
  • Deleting the previous T3 runtime before the fork passes verification.
